# GigaVibeMiptCode

`GigaVibeMiptCode` — консольный ИИ-ассистент на Python. Приложение работает через
OpenAI-compatible API, поддерживает ограничение контекста, конфигурацию
через YAML и переменные окружения, подстановку файлов, chunk режим для обработки больших
текстов, сброс истории, выход из CLI и streaming-ответы модели.

## Возможности

- чат с LLM через OpenAI-compatible API
- хранение истории сообщений
- передача истории в модель как контекста
- ограничение контекста по количеству сообщений
- ограничение контекста по количеству символов
- конфигурация через `config.yaml`
- конфигурация через переменные окружения
- приоритет ENV над YAML
- обработка `KeyboardInterrupt` во время ожидания ответа модели
- прикрепление текстовых файлов через синтаксис `@::path/to/file::`
- ограничение размера прикрепляемого файла до 5 МБ
- интерактивный режим обработки файла по чанкам
- деление файла на чанки по абзацам, нескольким абзацам или длине
- автоматическая обработка чанков через `-y`
- команда `/reset`
- команда `\q`
- streaming-ответы модели
- цветное оформление CLI через `rich`
- unit-тесты и HTML-отчёт покрытия.


## Назначение основных директорий

- `ai_chat/config` — загрузка и валидация конфигурации
- `ai_chat/llm` — клиент для OpenAI-compatible API
- `ai_chat/chat` — история, сообщения, ограничение контекста, сервис чата
- `ai_chat/files` — чтение файлов, подстановка attachments, деление на чанки
- `ai_chat/console` — CLI, команды, ввод и вывод в терминал
- `ai_chat/utils` — вспомогательные функции, в том числе нормализация текста
- `tests` — unit-тесты бизнес-логики

## Требования

- Python 3.10 или выше
- доступный OpenAI-compatible API
- для локального запуска можно использовать Ollama

## Конфигурация

Приложение можно настроить двумя способами:

1. через файл `config.yaml`
2. через переменные окружения.

Переменные окружения имеют приоритет над значениями из `config.yaml`

Файл `config.yaml` должен лежать в директории `final_project` рядом с `main.py`.
Пример конфигурации:

```yaml
api_key: ollama
api_host: http://localhost:11434/v1/
model: llama3.2
limit_messages: 20
limit_chars: 8000
temperature: 0.7
streaming: true
system_prompt: Ты полезный русскоязычный ассистент.
```

Поля конфигурации:

- `api_key` — ключ API для Ollama может быть любым непустым значением
- `api_host` — адрес OpenAI-compatible API
- `model` — имя модели
- `limit_messages` — максимальное количество сообщений в истории
- `limit_chars` — максимальное количество символов в истории
- `temperature` — температура генерации от 0 до 1
- `streaming` — включение потокового вывода
- `system_prompt` — системный промпт

Для примера настроек в проекте есть `config.example.yaml`.

## Переменные окружения

Поддерживаются следующие переменные:

```text
API_KEY
API_HOST
MODEL
LIMIT_MESSAGES
LIMIT_CHARS
TEMPERATURE
STREAMING
SYSTEM_PROMPT
```

Пример:

```bash
export API_KEY=ollama
export API_HOST=http://localhost:11434/v1/
export MODEL=llama3.2
export LIMIT_CHARS=8000
export LIMIT_MESSAGES=20
export TEMPERATURE=0.7
export STREAMING=true
```

## Локальный запуск с Ollama

Краткий сценарий локального запуска:

1. Установить Ollama.
2. Скачать модель.
3. Создать `config.yaml`.
4. Запустить проект.

Скачивание модели:

```bash
ollama pull llama3.2
```

Проверка Ollama через OpenAI-compatible endpoint:

```bash
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2",
    "messages": [
      {
        "role": "user",
        "content": "Привет! Ответь одним предложением."
      }
    ]
  }'
```

Минимальный `config.yaml` для Ollama:

```yaml
api_key: ollama
api_host: http://localhost:11434/v1/
model: llama3.2
streaming: true
system_prompt: Ты полезный русскоязычный ассистент.
```

Запуск проекта:

```bash
python main.py
```

## Запуск приложения

Запуск из директории проекта:

```bash
python main.py
```

После запуска пользователь попадает в интерактивный режим:

```text
>>> Привет
ИИ: Привет! Чем могу помочь?
```

Интерфейс оформлен через `rich`: при старте показывается приветственная панель,
ошибки выделяются красным, успешные действия — зелёным, а обычные ответы ассистента
выводятся в панели

## Команды CLI

Команды вводятся внутри уже запущенного приложения.

### Выход

```text
\q
```

В основном режиме завершает программу. В chunk-режиме завершает обработку файла и
возвращает пользователя в основной чат

### Сброс истории

```text
/reset
```

Очищает историю сообщений и экран терминала, но сохраняет системный промпт

### Обработка файла по чанкам

Поддерживаются оба варианта команды:

```text
/filechunk
/file_chunk
```

Примеры:

```text
/filechunk
/filechunk paragraph=3
/filechunk len=150
/filechunk paragraph=3 -y
/file_chunk len=150 -y
```

Параметры:

- без параметров файл делится по абзацам
- `paragraph=3` объединяет по 3 абзаца
- `len=150` делит файл по длине в символах
- `-y` автоматически обрабатывает все чанки без ожидания Enter.

Пример сценария:

```text
>>> /filechunk paragraph=3
Введите путь до файла:
>>> texts/article.txt
Принято. Что нужно сделать для каждого фрагмента?
>>> Кратко перескажи этот фрагмент.
```

## Прикрепление файлов к сообщению

Синтаксис прикрепления файла:

```text
@::path/to/file.py::
```

Пример:

```text
>>> Найди ошибку в коде: @::example.py::
```

Особенности:

- содержимое файла автоматически подставляется в сообщение
- можно прикрепить несколько файлов в одном сообщении
- максимальный размер одного файла — 5 МБ
- при ошибке чтения сообщение не отправляется в LLM
- относительные пути считаются относительно директории запуска

Если приложение запущено командой `cd final_project && python main.py`, то путь
`@::ai_chat/main.py::` будет относиться к директории `final_project`

## Контроль контекста

История сообщений передаётся в LLM как контекст. Чтобы контекст не становился слишком
большим, он ограничивается перед запросами к модели

- `limit_messages` ограничивает количество сообщений
- `limit_chars` ограничивает суммарное количество символов
- если лимит превышен, удаляются самые старые сообщения
- `system_prompt` сохраняется, если его можно сохранить при текущих лимитах
- если одно пользовательское сообщение длиннее лимита символов, оно обрезается слева.

Если заданы оба лимита, применяются оба условия

## Streaming-ответы

Если в конфиге указано:

```yaml
streaming: true
```

ответ модели выводится постепенно, по мере генерации.

Если указано:

```yaml
streaming: false
```

ответ выводится после полной генерации. В этом режиме ответ ассистента отображается
в панели `rich`

## Обработка ошибок

Приложение обрабатывает типовые ошибки и выводит понятные сообщения без лишнего traceback:

- отсутствие конфигурации
- невалидные значения конфигурации
- ошибки подключения к LLM API
- пустой ответ модели
- слишком большие файлы
- несуществующие файлы
- директория вместо файла
- ошибки чтения файлов
- некорректные команды
- `KeyboardInterrupt` во время ожидания ответа модели.

Также в проекте есть нормализация текста для случаев, когда локальная модель или
OpenAI-compatible сервер возвращает повреждённые Unicode-символы.
